# Tabs — design & plan (2026-07-16)

Component #16 (Tier B). A Nib-styled tab set that fixes the two things that make
"floater tabs" feel broken:

1. **No stuck scroll.** When a tall tab panel sits inside a page that also
   scrolls (content above + tabs + content below), reaching the panel's edge must
   *keep scrolling the page* — never trap the user until they fish for a scrollbar
   at the screen edge.
2. **A gutter between panels.** Swiping/animating from tab 1 to tab 2 shows a
   margin between the outgoing and incoming content so they never look glued into
   one sheet. It appears "as you scroll" (during the drag).

Plus the master-prompt requirements: **scrollable tab bar on overflow** and an
**indicator that animates position + width smoothly**.

## Core architectural decision (locked, user-approved)

**`NibTabs` owns exactly one vertical `Scrollable`.** The stuck-scroll bug is
caused by two independent same-axis `Scrollable`s that don't chain in Flutter. So
we never create a second one. `NibTabs` renders a single internal
`CustomScrollView` (the page scroll) whose sliver stack is:

| Sliver | Source | Behavior |
|---|---|---|
| header | `header` param (a box widget, wrapped `SliverToBoxAdapter`) | your "content above"; scrolls away |
| bar | `SliverPersistentHeader(pinned: true)` | **pins** under the header; horizontally scrollable on overflow; animated indicator |
| panel | the active tab's `builder`, sized to content, **no inner vertical scroll** | part of the one scroll → can never trap |
| footer | `footer` param (`SliverToBoxAdapter`) | your "content below"; scrolls in after the panel |

**Consumer contract:** put "above" content in `header`, "below" content in
`footer`, and **do not** wrap `NibTabs` in another vertical `ListView` /
`SingleChildScrollView` — that would reintroduce the nested-scroll bug `NibTabs`
exists to prevent. `NibTabs` is the page scroll. It expects a bounded height
(fills its parent, like any scroll view). Documented on the widget.

The only other `Scrollable`s in the tree are **horizontal** (the overflow bar and
the panel pager) — they don't compete with the vertical page scroll (Flutter's
gesture arena disambiguates by axis), so the "no vertical stuck edge" invariant
holds by construction.

## Panel pager (swipe + gutter + adaptive height)

The panel region is a **custom horizontal pager** (not `PageView`, so we control
the gutter and the content-driven height without fighting `PageView`'s
forced-viewport-height, which blocks natural-height measurement):

- Renders the active panel; during a horizontal drag also renders the neighbour
  being dragged in, both translated by the drag offset via `Transform.translate`.
- **Gutter:** a `panelGap` of empty space sits between adjacent panels during the
  drag, so they read as separate pages. Default `panelGap = 16`.
- **Switch:** `onHorizontalDragUpdate/End` (fling/threshold → snap to current or
  neighbour) **or** a tab tap. Both drive one `AnimationController` (`_page`, a
  fractional page position) that snaps to an integer index.
- **Adaptive height:** each panel reports its natural height via a size-reporting
  wrapper (`_MeasureSize`, post-layout callback → cache in `_heights`). The pager
  height = interpolate(`_heights[floor(page)]`, `_heights[ceil(page)]`, frac), so
  the region hugs the active panel's content and **reflows the footer smoothly**
  when heights differ. Unmeasured panels default to the current height for one
  frame until measured (imperceptible; same class as Bottom Sheet's documented
  one-frame settle).
- **Indicator sync:** the bar indicator's left/width interpolate off the same
  fractional `_page` value → it glides *with* the finger, not after.

If adaptive per-panel height measurement proves disproportionately fiddly during
TDD, the documented fallback is a fixed pager height = the tallest panel (footer
then sits below the tallest; shorter tabs show blank space) — logged as a Known
Gap, not silently shipped.

## Tab bar

- **`scrollable: false` (default):** tabs share width equally (`Row` of
  `Expanded`); indicator geometry is pure math (`slotWidth = barWidth / n`,
  `left = index * slotWidth`), no measurement.
- **`scrollable: true`:** tabs take intrinsic width inside a **horizontal**
  `SingleChildScrollView`; on switch the bar auto-scrolls the active tab into
  view. Indicator left/width come from measured tab rects (`GlobalKey` per tab,
  post-layout).
- **`indicatorStyle`:** `underline` (default — a `primary` bar under the active
  tab), `pill` (a filled `secondary`/`primary` rounded rect behind the label), or
  `none`.
- Colors/radii all from `NibTheme.of(context)` (active = `primary`, idle =
  `mutedForeground`). Light + dark for free.

## API

```dart
NibTabs({
  Key? key,
  required List<NibTab> tabs,        // NibTab(label, icon?, builder)
  int initialIndex = 0,
  NibTabsController? controller,     // optional; owns one internally if null
  Widget? header,                    // "content above"; scrolls away
  Widget? footer,                    // "content below"; scrolls after panel
  bool scrollable = false,           // overflow bar scroll (master-prompt param)
  NibTabsIndicatorStyle indicatorStyle = NibTabsIndicatorStyle.underline,
  double panelGap = 16,              // gutter between panels + margin before footer
  bool swipeable = true,             // horizontal swipe to change tab
  bool animated = false,             // nib_motion opt-in (panel-content fade)
  NibTransition? transition,
  ValueChanged<int>? onChanged,
})

class NibTab {
  const NibTab({required this.label, this.icon, required this.builder});
  final String label;
  final IconData? icon;
  final WidgetBuilder builder;       // built lazily when the tab is first shown
}

enum NibTabsIndicatorStyle { underline, pill, none }
```

### `NibTabsController`

A thin `ChangeNotifier` (mirrors `NibAccordionController`'s ownership pattern):
exposes `index`, `animateTo(int)` / `jumpTo(int)`; the widget creates+owns+
disposes one when `controller == null`, rebinds on controller-swap in
`didUpdateWidget`. The widget's private `State` holds the real engine (`_page`
`AnimationController` + `_heights`) and keeps the controller's `index` in sync.

## nib_motion contract (flagged §1.4/§8.5 deviation)

Same precedent as **Accordion** (height reveal) and **Bottom Sheet** (drag
transform): the indicator glide, pager translate, and adaptive height are
**gesture/layout-driven `AnimationController`s** — layout size/position can't route
through `nib_motion`'s transform/opacity/rotate model. The contract is still
honoured for the decorative part: when `animated: true` the panel-content swap is
wrapped in a `NibMotion` fade (keyed by index), so **`animated: true` builds
`NibMotion` and `animated: false` builds zero** (tested). Swipe/tap still work
with `animated: false`; the indicator/height just move without the extra fade.

## Tests (TDD)

1. Renders `tabs.length` tab labels; the `initialIndex` panel is visible, others
   not built (lazy).
2. **Tap** a tab → its panel shows, `onChanged` fires with the index, indicator
   moves to it.
3. **Swipe** the panel horizontally → switches tab (when `swipeable`), and does
   **not** switch when `swipeable: false`.
4. Indicator geometry updates on switch (position/width differ between tab 0 and
   tab 1).
5. **Structural no-stuck:** the panel introduces **no vertical `Scrollable`** —
   assert no `SingleChildScrollView`/`ListView` with `Axis.vertical` inside the
   panel subtree; the only vertical scroll is the one internal `CustomScrollView`.
6. **Gutter:** with two panels mid-drag, a `panelGap` separates them (assert the
   gap widget / spacing is present during a drag, and as trailing margin before
   `footer`).
7. Adaptive height: switching to a taller/shorter tab changes the pager height
   (footer offset moves).
8. `animated` on → `find.byType(NibMotion)` findsWidgets; `animated` off →
   `findsNothing`.
9. `NibTabsController.animateTo` drives the index; external controller is **not**
   disposed by the widget, an internally-owned one **is** (dispose-safety).
10. `header` scrolls away while the bar stays pinned (scroll the view, assert the
    bar's position is unchanged after the header has scrolled off).

## Example demos (`tabs_examples.dart`)

- **Minimal** — 2 tabs, short content, default underline.
- **Common** — 3 tabs with icons, `pill` indicator, `scrollable: true` bar that
  overflows so the auto-scroll-into-view is visible.
- **Advanced (the whole point)** — `header` (a tall hero block) + several tabs
  whose panels are long lists of differing heights + a `footer`, all inside one
  page: proves continuous scroll, pinned bar, no stuck edge, gutter on swipe, and
  footer reflow. This is the demo that reproduces (and shows fixed) the reported
  floater-tab bug.

## Known-gap candidates (log if hit)

- Content-sized panels build their full content eagerly (not lazily virtualised).
  Fine for forms/cards/moderate lists — the normal tab case. A single tab holding
  a *thousands-of-rows lazy list* is out of scope for this single-scroll model
  (that needs the `NestedScrollView` variant, which breaks footer-below). Log as a
  Known Gap if the fallback is taken.
- Adaptive-height fallback to tallest-panel fixed height (see pager section),
  should measurement prove disproportionate.
