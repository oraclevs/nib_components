# NibButton — design & build plan (2026-07-17)

Component #18 (Tier B, §6). The **reference** button whose `loading`/`disabled`
pattern other components follow. Built directly with TDD in the main session
(per `nib_components/CLAUDE.md`), no subagents.

## API

```dart
NibButton({
  String? label,                          // nullable → enables icon-only
  VoidCallback? onPressed,                // null ⇒ disabled
  NibButtonVariant variant = NibButtonVariant.primary,
  NibButtonSize size = NibButtonSize.md,  // sm | md | lg preset
  double? height,                         // custom box height (overrides preset)
  double? width,                          // custom box width (overrides preset)
  EdgeInsetsGeometry? padding,            // null → preset padding (0 for icon-only)
  BorderRadius? borderRadius,             // null → pill/default; overrides pill
  bool loading = false,
  bool disabled = false,
  Widget? leadingIcon,
  Widget? trailingIcon,
  Widget? content,                        // fully custom child (replaces label/icons)
  bool expand = false,                    // full-width
  bool pill = false,                      // radiusPill vs radiusDefault
  String? tooltip,
  String? semanticLabel,
  bool animated = false,
  NibTransition? transition,
  Widget? loadingWidget,                  // custom indicator (replaces spinner)
  String? loadingText,                    // text beside the indicator
})
```

### Loading (revised 2026-07-17 after review)
- Content while loading = `[indicator][optional loadingText]`. `indicator` =
  `loadingWidget` if given, else the default `NibCircularLoader`. So all of
  text-only, widget-only, and both are supported (loadingText alone ⇒ spinner +
  text).
- **The button does not resize when loading starts.** The normal content is kept
  in the tree via `Visibility(visible:false, maintainSize:true, …)` +
  `ExcludeSemantics` to reserve its footprint, and the loading content is
  overlaid centred in a `Stack`. A content-sized button keeps its width; a
  fixed/preset-sized button is unaffected either way.

`NibButtonVariant { primary, secondary, outline, ghost, destructive }`
`NibButtonSize { sm, md, lg }`

### Deviations from MASTER_PROMPT §4 (flag in PROGRESS)
- `label` is `String?` (not `required String`) to allow **icon-only** buttons.
  `assert` at least one of `label` / `leadingIcon` / `trailingIcon`; `assert`
  `semanticLabel != null` when `label == null`.
- Animation control param is `transition: NibTransition?` (the real `nib_motion`
  type used across this package), **not** §4's `NibAnimationPreset? animation`,
  which was never adopted in this repo.
- Added `height`/`width`/`expand`/`pill` per user request during brainstorming.

## Sizing

| size | visual h | text | h-pad | v-pad | icon |
|------|----------|------|-------|-------|------|
| sm   | 36       | 13   | 12    | 8     | 16   |
| md   | 44       | 14   | 16    | 10    | 18   |
| lg   | 52       | 16   | 20    | 14    | 20   |

- `height`/`width` override the preset **box** dimensions exactly (preset still
  drives text/icon/padding). Both null ⇒ content-sized; `expand` ⇒ full-width;
  icon-only ⇒ square (w == h == height).
- **≥48 logical hit target is independent of visual size** (§1.1 a11y): the
  visual box is the exact requested size (44 = 44); the ≥48 tap area is invisible
  padding *around* the box (Flutter padded-tap-target trick). No forced-min
  conflict with custom small sizes.

## Identical geometry across variants (locked requirement)

A filled 44×44 and an outline 44×44 **must render the same size**, footprint and
inner content box. Mechanism:
- **Every variant reserves the same 1px border inset.** Outline draws it visible
  (`border` token); primary/secondary/ghost/destructive draw it *transparent*.
  Flutter `BoxDecoration` borders paint **inside** the bounds, so the border never
  grows the box and the inner content rect is identical across variants.
- **Focus ring is a layout-neutral overlay** (painted outside the box, not part of
  layout), applied equally to all variants, visible on focus only ⇒ a focused
  outline is never bigger than a filled.

## Variant tokens

| variant | fill | text | border (1px) | hover |
|---------|------|------|--------------|-------|
| primary | `primary` | `primaryForeground` | transparent | darken overlay |
| secondary | `secondary` | `secondaryForeground` | transparent | darken overlay |
| outline | transparent | `foreground` | `border` | `muted` fill |
| ghost | transparent | `foreground` | transparent | `muted` fill |
| destructive | `destructive` | white | transparent | darken overlay |

## States
- **hover**: subtle overlay (`muted` fill for outline/ghost; darken for filled).
- **pressed**: ripple — always on, both `animated` modes (native feedback §1.1).
- **focus**: `ring` overlay outline.
- **disabled / `onPressed == null`**: 0.5 opacity, no ripple, `Semantics(enabled:false)`.
- **loading**: reuse existing `NibCircularLoader` in place of content, taps blocked,
  `Semantics` announces busy. `loadingWidget` overrides the spinner.

## Native build (§1.1)
`Semantics(button:true, enabled:, label:)` → `FocusableActionDetector`
(focus + hover + `Enter`/`Space` via `Shortcuts`/`Actions`) → `InkWell`/`InkResponse`
ripple (token splash) → sized `DecoratedBox` content. Mouse cursor click / forbidden.
Not a bare `Container` + `GestureDetector`.

## Animation (§1.4)
- `animated: false` ⇒ **zero `NibMotion`** built (ripple/press still work — native
  feedback, not motion).
- `animated: true` ⇒ `nib_motion` **tap scale-pop**: a `NibMotion` keyed by a tap
  counter replays `initial: NibAnim(scale: 0.94) → NibAnim.identity`. Same
  decorative-opt-in idiom as `NibAccordion`'s chevron. Default transition ~120ms ease.

## Responsive (§1.7)
Long label ellipsizes (`Flexible` + `TextOverflow.ellipsis`), never overflows a
narrow parent. Narrow-width widget test included.
